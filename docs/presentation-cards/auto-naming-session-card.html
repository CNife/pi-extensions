auto-naming-session
标题跟着对话一起演化

自动生成并刷新会话标题，让标题始终反映当前的真实主题。
蔡涛(CNife)
2026.06.15
v0.2.0

通常做法：只看开头

  • 标题取对话前几条消息生成，不再更新
  • 对话逐渐演进到真正主题，标题还停留在开头
  • 回头找历史会话时，标题和内容对不上

auto-naming：持续演进

  • 第一条消息到后立即生成初始标题
  • 每 N 个 turn 增量刷新——只看新内容，不重复总结
  • 标题随对话逐步收敛到真实主题

标题演进示例

▸
turn 1 · 用户发消息
「PostgreSQL 连接失败」
▸
turn 2–5 · 排查配置
「PG 连接池配置排查」
▸
turn 6–12 · 深入源码
「连接池性能分析与优化方案」
▸
turn 13+ · 重构
「重写连接池模块——决策记录」

核心机制

增量刷新：每次只总结自上次命名后的新对话内容（基于 session entry id 追踪），不会把整段历史丢给 LLM 重新生成。
  • 首条触发——第一条 user message 到达后立即生成初始标题，不等待 agent 回合
  • 自动刷新——默认每 10 个 turn 触发一次，由 agent_end 事件驱动
  • 手动保护——用户手动改过标题后，auto-naming 检测到变化并停止覆盖

配置项

字段默认说明
auto_refresh_turns10每 N turn 刷新，null 禁用
modelnull指定命名模型（provider/modelId），null 复用当前模型
language"english"标题语言
