description: 为变更的代码编写测试，确保覆盖核心逻辑和边界情况
argument-hint: "[变更目录]"
---

读取当前变更计划的 `change.md` 最新变更摘要获取文件清单，为变更代码编写测试，追加测试记录。

### 变更目录解析

按以下优先级确定当前变更目录：
1. `$ARGUMENTS` 非空 → 直接使用
2. `changes/.active_change` 存在 → 读取其内容作为目录名（去掉首尾空白）
3. 执行 `ls changes/` 找到最近 `YYYYMMDD-*` 子目录 → 向用户确认
4. 以上均无 → 提示用户先执行 `/new-change`

确定后的变更目录记为 `$CHANGE_DIR`，下文所有文件路径均相对于项目根目录。

### 输入

- **变更范围**：`$CHANGE_DIR/change.md` 最新变更摘要中的文件清单
- **上下文**：`$CHANGE_DIR/tasks.md`、`$CHANGE_DIR/plan.md`

### 流程

1. 读取 `change.md`，定位最新变更摘要节（「编码完成」或「修复完成」），提取变更文件清单
2. 读取 `tasks.md`，了解各任务的验证方式
3. **确定测试范围**：变更了哪些模块/函数，就为哪些模块/函数写测试——而非一刀切只测最上层
4. **编写测试**：
   - 每个被修改的函数至少一条正向用例
   - 边界情况：空输入、极值、异常路径
   - 测试文件放在 `tests/` 目录（或项目约定的测试目录），命名对应源文件
5. **运行项目的测试命令**（如 `pytest`、`npm test`、`cargo test` 等），确保全部通过
6. 若失败 → 修复测试代码，最多 3 次尝试
7. 追加测试记录到 `change.md`

### 验证规则

- 测试必须全部通过（退出码 0）
- 用例数 > 0（避免空测试文件）
- 失败时根据错误信息修复，最多重试 3 次

### 输出格式

向 `$CHANGE_DIR/change.md` 追加（不覆盖已有内容），版本号顺延：

```markdown
---

# 变更 v{N}：测试编写

## 测试文件

| 文件 | 对应源码 | 用例数 |
|------|---------|--------|
| tests/test_a.py | src/a.py | 5 |

## 测试覆盖

| 测试类型 | 数量 |
|---------|------|
| 正向用例 | 3 |
| 边界情况 | 1 |
| 异常路径 | 1 |

## 验证结果

- （项目的测试命令）：通过（N passed）
```

### 停止条件

- 变更范围无法确定 → 输出说明并停止
- 测试全部通过且记录追加完毕 → 输出「进入 review-test」指引并停止
- 3 次修复后测试仍失败 → 输出失败详情并停止
