---
description: 读取tasks.md分层计划，按层顺序逐个执行编码任务并验证
argument-hint: "[变更目录]"
---

读取当前变更计划的 `tasks.md` 和 `plan.md`，按并行分层计划逐层推进：每层内逐个执行编码任务，完成后运行验证命令，全部通过则进入下一层。

### 变更目录解析

按以下优先级确定当前变更目录：
1. `$ARGUMENTS` 非空 → 直接使用
2. `changes/.active_change` 存在 → 读取其内容作为目录名（去掉首尾空白）
3. 执行 `ls changes/` 找到最近 `YYYYMMDD-*` 子目录 → 向用户确认
4. 以上均无 → 提示用户先执行 `/new-change`

确定后的变更目录记为 `$CHANGE_DIR`，下文所有文件路径均相对于项目根目录。

### 输入

- **主输入**：`$CHANGE_DIR/tasks.md` — 任务拆解与分层计划
- **上下文**：`$CHANGE_DIR/plan.md` — 变更方案全文

### 流程

```
读取 tasks.md → 解析 wave 列表
  ↓
对每一层 wave：
  对层内每个任务（按 ID 顺序）：
    1. 编码：按任务描述实现变更
    2. 验证：运行该任务的验证命令
    3. 通过 → 下一个任务；失败 → 修复（最多 3 次）
  该层全部通过 → 进入下一层
  ↓
所有 wave 完成 → 输出完成总结
```

### 编码规则

- 每个任务只修改其「涉及文件」列指定的文件，不动无关代码
- 修改已有文件时，用精确的文本替换（oldText → newText），不重写整个文件
- 新建文件时，确认父目录存在
- 多个任务修改同一文件时，后续任务在前序任务的基础上修改
- 遇到 plan.md 和 tasks.md 之间存在歧义时，以 plan.md 为准

### 验证规则

- 验证命令直接来自 tasks.md 子任务清单的「验证方式」列
- 每完成一个任务立即验证，不攒到层末尾
- 验证失败时，根据错误信息修复，最多重试 3 次
- 3 次后仍不通过 → 停止，输出该任务的失败信息和手动修复指引

### 更新 change.md

所有 wave 完成后，将编码摘要追加到 `$CHANGE_DIR/change.md`（追加，不覆盖已有内容）。

1. 读取 change.md，统计已有 `# 变更 v` 节数，确定版本号为 N+1（无则 v1）
2. 追加以下格式的章节：

```markdown
---

# 变更 v{N}：编码完成

## 产出文件

- src/a.py（修改）
- src/b.py（新建）

## 执行摘要

| 层 | 任务数 | 完成 | 失败 |
|----|--------|------|------|
| 1 | 2 | 2 | 0 |
| 2 | 2 | 2 | 0 |

## 变更文件清单

| 文件 | 对应任务 | 操作 |
|------|---------|------|
| src/a.py | Task1 | 修改 |
| src/b.py | Task3 | 新建 |
```

- **产出文件**：列出所有变更的文件及其操作类型（修改/新建/删除）
- **执行摘要**：每层的任务数和完成/失败统计
- **变更文件清单**：一一对应，供 review-code 使用

### 停止条件

- tasks.md 不存在或格式无法解析 → 停止
- plan.md 不存在 → 停止
- 某任务验证失败且 3 次修复不通过 → 停止，报告失败任务及已完成的任务清单。手动修复后重新运行 write-code：已完成层级的代码仍在磁盘上，重新执行时会快速通过
- 所有层完成 → 更新 change.md，输出完成总结，停止
