# fix-code 阶段 — 完整操作说明

## 输入

- **审阅报告**：`$CHANGE_DIR/change.md` 最新「代码审阅」节的「未通过项详情」表格
- **上下文**：`$CHANGE_DIR/tasks.md`、`$CHANGE_DIR/plan.md`

## 流程

1. 读取 change.md，定位最新「代码审阅」节，提取「未通过项详情」表格
2. 如果没有未通过项 → 直接停止，提示审阅已通过
3. **展示问题清单**，逐类列出：
   - 🔴 阻断项（范围超出、Hard Stops）
   - 🟡 建议项（目标部分实现、lint 残留）
   - 🔵 注意项（格式残留）
4. **确定讨论模式**：
   - **快速模式**：阻断项均建议修复、建议项默认可跳过时，一次性列出完整清单和推荐处理方式
   - **逐条模式**：问题之间的处理策略有显著分歧时，逐条讨论
5. **讨论修复**：
   - 阻断项 → 必须先处理
   - 建议项 → 用户可选择跳过
   - 注意项 → 默认跳过
6. **确定修复清单**：汇总用户确认要修复的项目，向用户确认修复范围
7. **根因断言（仅限 bug 修复）**：对于 🔴 阻断中的 bug 类问题（非 lint/format），
   修复前必须写根因声明：
   ```
   Root cause: <文件>:<行号> — <一句话原因>
   ```
   根因声明必须：
   - 精确到文件:行号
   - 能独立验证（改变声明的原因后 bug 应该消失）
   - 不能是"我觉得"、"可能是"、"大概"这类猜测
   如果无法写出合格的根因声明，回退到 /hunt 调试流程。
8. **可证伪假设（重修复用）**：第一次修复失败后，后续每次修复尝试前必须写可证伪假设：
   ```
   Hypothesis: 如果根因是 X，那么改变 Y 后 bug 将不再复现
   ```
   假设必须：
   - 明确指出改变什么（哪个文件、什么逻辑）
   - 预测结果必须是客观可验证的（测试通过、命令退出码 0）
   - 不能是"再试一次看看"
   验证后无论假设是否成立，记录到 change.md。
9. **执行修复**：按清单逐项修复代码
   - 范围超出 → 删除超出范围的代码，或将遗漏文件补充到 tasks.md
   - Hard Stops → 消除漏洞、移除凭证、回退依赖等
   - Lint 残留 → 按问题描述修复代码
10. **运行 Format 和 Lint 检查**，确保修复没有引入新问题
11. 追加修复记录到 change.md

## 输出格式

向 `$CHANGE_DIR/change.md` 追加：

```markdown
---

# 变更 v{N}：修复完成

## 修复决策

| # | 审阅问题 | 严重程度 | 决策 | 理由 |
|---|---------|---------|------|------|
| 1 | src/b.py 超出范围 | 🔴 阻断 | 修复 | 用户确认移除 |

## 根因分析

| # | 问题 | 根因声明 | 假设记录 |
|---|------|---------|---------|
| 1 | 登录返回 500 | src/auth.py:42 — dep array missing userId | H1: 加 userId 后通过 ✅ |

## 变更文件清单

| 文件 | 操作 | 说明 |
|------|------|------|

## 修复后验证

- Format 检查：通过 / 未通过
- Lint 检查：通过 / 未通过
```

### STATE 更新

追加修复记录后，更新 change.md 顶部的 STATE 块（当前阶段、已完成项）。

### Handoff 格式（3 次修复失败时自动追加）

```markdown
---

## HANDOFF (<YYYY-MM-DD HH:MM>)
- 问题: <原始问题描述>
- 已测假设:
  - H1: <假设内容> → <结果>（已排除）
  - H2: <假设内容> → <结果>（已排除）
- 已排除路径: <逐条列出>
- 仍然可能的根因: <推测列表>
- 建议下一步: <建议的下一假设或方向>
```

## 约束

- 每类问题逐一讨论，不批量假设用户意图
- 阻断项不可跳过——若用户坚持不修，明确记录决策和风险
- 修复操作仅限于用户确认的清单，不扩大范围
- 修复后必须重新运行 format/lint 检查

## 停止条件

- 审阅报告中没有未通过项 → 提示审阅已通过，进入 write-test，停止
- 用户确认修复清单后所有修复完成并追加记录 → 输出「进入 review-code」指引并停止
- 同一问题的修复尝试达到 3 次且仍未通过 → 自动产出 handoff 快照到 change.md，然后停止
- **Handoff 后不可再次尝试修复**——用户需审视方案或切换调试方式
