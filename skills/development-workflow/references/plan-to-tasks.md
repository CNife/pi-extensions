# plan-to-tasks 阶段 — 完整操作说明

## 输入

- 主输入：`$CHANGE_DIR/plan.md`，已锁定不可变
- 参考：`$CHANGE_DIR/change.md`（如有），仅了解审核历史，不推翻 plan.md

## 拆解规则

1. 一个子任务对应一个可独立验证的变更点——完成后能用一条明确的检查命令确认正确性
2. 修改配置 + 同步更新所有引用处 = 一个子任务。新建一个模块文件 = 一个子任务。重构一个函数的所有调用方 = 一个子任务
3. 不按文件行号或字段粒度机械切分
4. **优先按垂直切片拆分**：每个子任务应端到端穿透所有层（schema + API + 逻辑 + 页面 + 验证），而非按技术层水平拆分（所有 schema → 所有 API → 所有 UI → 所有测试）。
5. **例外**：当垂直切片会导致大量重复工作（如多个切片共用同一个底层 API）时，才考虑水平切一层做基础后再垂直切片。

### 示例

```markdown
# ✅ 正确：垂直切片
| ID | 子任务 | 涉及文件 | 验证方式 |
|----|--------|---------|---------|
| T1 | 用户注册（schema + API + 页面 + 验证） | schema/user.py, api/register.py, pages/... | pytest -k register |
| T2 | 用户登录（schema + API + 页面 + 验证） | schema/user.py, api/login.py, pages/... | pytest -k login |

# ❌ 错误：水平切片
| ID | 子任务 | 涉及文件 | 验证方式 |
|----|--------|---------|---------|
| T1 | 实现所有 schema | schema/*.py | —（无法验证）|
| T2 | 实现所有 API | api/*.py | —（无页面配合）|
```

## 依赖分析规则

1. 子任务 B 调用了子任务 A 创建的接口/模块 → B 依赖 A
2. 两个子任务修改不同模块、无接口依赖 → 独立，可并行
3. 不凭空制造依赖

## tasks.md 输出格式

写入 `$CHANGE_DIR/tasks.md`（覆盖写入）：

```markdown
# 任务拆解

> 基于：plan.md
> 生成时间：YYYY-MM-DD
> 总子任务数：N / 并行层数：M

## 来源决策（继承自 plan.md）

本任务拆解基于 plan.md 的以下决策：

| 决策 | 选型 | 对任务的影响 |
|------|------|-------------|
| 使用 GraphQL | 优化批量查询，损失缓存 | 每个 API 切片需包含 schema 定义 |
| JWT 7 天过期 | 优化 UX，损失安全 | 无需 refresh token 机制 |

## 子任务清单

| ID | 子任务 | 涉及文件 | 验证方式 |
|----|--------|---------|---------|
| T1 | xxx | a.py | xxx |
| T2 | xxx | b.py, c.py | xxx |

## 并行分层计划

### 第 1 层（无依赖，可并行）

- T1: xxx
- T3: xxx

### 第 2 层（依赖第 1 层）

- T2: xxx（依赖 T1）
```

## change.md 追加格式（v{N}）

tasks.md 写入完毕后，将变更摘要追加到 `$CHANGE_DIR/change.md`（追加，不覆盖已有内容）。

```markdown
---

# 变更 v{N}：任务拆解

## 产出文件

tasks.md

## 变更概述

将 plan.md 拆解为 {总数} 个可独立验证的子任务，按 {层数} 个并行层排列。

## 关键决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | xxx | xxx |

## 任务摘要

| ID | 子任务 | 涉及文件 |
|----|--------|---------|
| T1 | xxx | a.py |

## 并行分层

| 层 | 包含任务 | 依赖 |
|----|---------|------|
| 1 | T1, T3 | 无 |
| 2 | T2 | T1 |
```

- **关键决策**：仅记录直接影响任务拆分结构的决策，不记录业务决策
- **任务摘要**：只保留 ID + 子任务 + 涉及文件三列
- **并行分层**：每层列出包含的任务 ID，依赖列说明该层依赖的上一层任务

### STATE 更新

追加后更新 change.md 顶部的 STATE 块（当前阶段、已完成项）。

## 停止条件

- plan.md 不存在或无法解析 → 停止
- plan.md 中存在无法确定子任务边界的模糊条目 → 提问，不猜测
- tasks.md 写入完毕且 change.md 追加完毕 → 停止，不进入执行
