# review-plan 阶段 — 完整操作说明

## 审核规则

1. 仅以 `$CHANGE_DIR/plan.md` 原始内容为依据，不引入外部信息，不主观评判方案合理性
2. 先检查范围偏差：plan.md 是否完整覆盖了变更需求？有无遗漏或画蛇添足？
3. 再检查表述模糊、逻辑矛盾、内容疏漏
4. **检查术语一致性**（新增）：若 `$CHANGE_DIR/glossary.md` 存在，检查 plan.md 中的术语使用是否与 glossary 一致。若 glossary 缺失但有明显术语歧义，建议维护 glossary。
5. **检查假设合理性**（新增）：plan.md 中「关键假设」是否合理？是否有未声明的隐含假设？假设不成立的后果是否已考虑？
6. 每条问题标注具体位置（章节/段落标题）、严重程度（🔴 阻断 / 🟡 建议）、详细描述
7. 判断标准：阻断级问题不解决则后续步骤无法执行；建议级问题可边做边修正
8. 修改结论在用户确认后再追加到 change.md，不得在确认前写入
9. 证据不足时只追问最小必要字段，不编造问题
10. **审核完成后同步更新 plan.md**：审计结论追加到 change.md 后，必须将 plan.md 中对应的错误/遗漏一并修正，避免审核流于形式

## 输出格式

### 第一步：输出审核总览和问题清单

```markdown
## 审核总览

| 类别 | 数量 | 状态 |
|------|------|------|
| 范围偏差 | N | 待确认 |
| 模糊表述 | N | 待确认 |
| 术语一致性 | N | 待确认 |
| 假设合理性 | N | 待确认 |
| 逻辑矛盾 | N | 待确认 |
| 内容疏漏 | N | 待确认 |

## 问题清单
...
```

### 第二步：追加审核结论到 change.md

```markdown
---

# 变更 v{N}：方案审核

> 基于：plan.md

## 审核结论

- 范围偏差：N 项（🔴 N / 🟡 N）
- 模糊表述：N 项（🟡 N）
- 术语一致性：N 项（🔴 N / 🟡 N）
- 假设合理性：N 项（🔴 N / 🟡 N）
- 逻辑矛盾：N 项（🔴 N / 🟡 N）
- 内容疏漏：N 项（🔴 N / 🟡 N）

## 修改记录

| # | 问题 | 严重程度 | 处理 |
|---|------|---------|------|
| 1 | xxx | 🔴 阻断 | xxx |
| 2 | xxx | 🟡 建议 | xxx |
```

### 第三步：更新 change.md STATE 块

追加审核结论后，更新 change.md 顶部的 STATE 块：

```
## STATE
- 当前阶段: review-plan（完成）
- 已完成: plan.md ✅, plan-review ✅
...
- 最后更新: <YYYY-MM-DD HH:MM>
```

### 第四步：同步更新 plan.md

修改结论确认后，除追加 change.md 外，还需同步更新 `plan.md` 中对应的错误或遗漏。如：

- 表述不一致 → 统一术语
- 逻辑矛盾 → 修正矛盾项
- 内容疏漏 → 补充缺失内容

## 停止条件

- plan.md 不存在 → 提示用户先执行 write-plan，停止
- 所有问题已确认、修改结论已追加到 change.md **且 plan.md 已同步更新** → 停止
