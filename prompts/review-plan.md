---

审核当前变更计划的 `plan.md`，排查四类问题（范围偏差、表述模糊、逻辑矛盾、内容疏漏），与用户确认后，将修改结论追加到 `change.md`。

### 变更目录解析

按 development-workflow skill 中的变更目录解析规则确定 `$CHANGE_DIR`。

### 审核规则

1. 仅以 `$CHANGE_DIR/plan.md` 原始内容为依据，不引入外部信息，不主观评判方案合理性
2. 先检查范围偏差：plan.md 是否完整覆盖了变更需求？有无遗漏或画蛇添足？
3. 再检查表述模糊、逻辑矛盾、内容疏漏
4. 每条问题标注具体位置（章节/段落标题）、严重程度（🔴 阻断 / 🟡 建议）、详细描述
5. 判断标准：阻断级问题不解决则后续步骤无法执行；建议级问题可边做边修正
6. 修改结论在用户确认后再追加到 change.md，不得在确认前写入
7. 证据不足时只追问最小必要字段，不编造问题

### 输出格式

第一步：输出审核总览和问题清单。

```markdown
## 审核总览

| 类别 | 数量 | 状态 |
|------|------|------|
| 范围偏差 | N | 待确认 |
| 模糊表述 | N | 待确认 |
| 逻辑矛盾 | N | 待确认 |
| 内容疏漏 | N | 待确认 |

## 问题清单

### 范围偏差

- **位置**：xxx
- **严重程度**：🔴 阻断
- **问题**：xxx
- **待确认**：xxx

### 模糊表述

- **位置**：xxx
- **严重程度**：🟡 建议
- **问题**：xxx
- **待确认**：xxx

...

```

第二步：用户确认问题后，追加审核结论到 `$CHANGE_DIR/change.md`。

追加格式：

```markdown
---

# 变更 v{N}：方案审核

> 基于：plan.md

## 审核结论

- 范围偏差：N 项（🔴 N / 🟡 N）
- 模糊表述：N 项（🟡 N）
- 逻辑矛盾：N 项（🔴 N / 🟡 N）
- 内容疏漏：N 项（🔴 N / 🟡 N）

## 修改记录

| # | 问题 | 严重程度 | 处理 |
|---|------|---------|------|
| 1 | xxx | 🔴 阻断 | xxx |
| 2 | xxx | 🟡 建议 | xxx |
```

### 停止条件

- plan.md 不存在 → 提示用户先执行 write-plan，停止
- 所有问题已确认、修改结论已追加到 change.md → 停止
