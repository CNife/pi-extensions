---
description: 根据变更内容更新项目文档，包括README、AGENTS、docs/等
argument-hint: "[变更目录]"
---

读取当前变更计划的 `change.md` 完整变更历程，评估本次变更对项目文档的影响，更新相关文档并追加记录。

### 变更目录解析

按 development-workflow skill 中的变更目录解析规则确定 `$CHANGE_DIR`。

### 输入

- **变更历程**：`$CHANGE_DIR/change.md` 全部内容
- **上下文**：`$CHANGE_DIR/plan.md`、`$CHANGE_DIR/tasks.md`

### 流程

1. 读取 `change.md` 完整内容，理解本次变更做了什么
2. 列出项目中可能受影响的文档：
   - `README.md` — 项目简介、安装说明、快速开始
   - `AGENTS.md` — AI 协作规范（文件地图、开发规则、已知问题）
   - `docs/` — 补充文档
   - 项目根目录其他 `.md` 文件
3. **逐文件判断是否需要更新**，向用户展示：

   ```
   文档影响评估：

   | 文件 | 影响 | 建议 |
   |------|------|------|
   | README.md | 无 | 不更新 |
   | AGENTS.md | 有：流水线新增步骤 | 更新「已知问题」或「当前进度」 |
   | workflow.md | 有：流水线已扩展 | 更新流程图 |
   ```

4. 用户确认后，逐一更新需要修改的文档
5. 追加文档更新记录到 `change.md`

### 更新原则

- 只修改与本次变更直接相关的内容，不动无关章节
- 修改已有文件时用精确的文本替换，不重写整个文件
- 新增内容保持与现有文档一致的风格和结构
- 删除过时信息（如旧的步骤描述），但保留历史引用

### 输出格式

向 `$CHANGE_DIR/change.md` 追加（不覆盖已有内容），版本号顺延：

```markdown
---

# 变更 v{N}：文档更新

## 更新的文档

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| README.md | 修改 | 更新流水线步骤说明 |
| AGENTS.md | 修改 | 更新已知问题 |
```

### 停止条件

- 用户确认无文档需要更新 → 停止，本次变更完成
- 所有需要更新的文档已更新且记录追加完毕 → 停止，本次变更完成
